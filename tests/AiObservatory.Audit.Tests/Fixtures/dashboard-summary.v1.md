# Shared synthetic summary fixture

`dashboard-summary.v1.json` is a cross-language, hand-calculated reference case. Decimal amounts are strings; consumers must retain them losslessly. The event snippets inherit this complete default: date 2026-10-20 UTC, provider `provider`, null model (aggregate key empty string), source `local`, local telemetry/subscription provenance, tokens input10/output20/cacheRead null/cacheWrite3/cacheWrite1h null/thought7. Array position supplies a distinct opaque row identity. Each event overrides the accounting basis, cost and savings. Spend snippets are billed ledger entries on that date and source; signed refunds stay signed.

The `expected` array is literal captured summary data, independent of the Audit implementation. USD ledger10 minus refund2 stays native USD8; native EUR5 stays separate; the already frozen GBP amounts sum to10.65. The list-price subtotal1.005 rounds to1.01. Cache savings-0.125 +0.25 =0.125, displayed0.13. One unknown notional cost and two unknown savings observations retain qualifiers. `none` represents a known zero without adding unknown counts. Missing cost buckets elsewhere remain null, rather than zero.

The public summary fields follow the dashboard summary names, with `billedNative` added per native currency (`groupKey` is its currency). Other values use `groupKey=all`. Count values use the ISO no-currency marker `XXX`, exact integer values and integer formatted strings. Money uses its explicit currency and invariant two-decimal formatted strings without a currency symbol. `missingQualifiers` lists required diagnostic codes; an additional per-notional qualifier is also emitted. Future frontend tests should run the production summary on equivalent aggregates and compare against these literals; they must never populate actual values by calling the independent Audit reference.
