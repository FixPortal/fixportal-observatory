# Plans and specs archive

These are the design specs and implementation plans that were written before each
piece of work, kept as a historical record of why the code looks the way it does.

**They are archival, not documentation.** Read them for intent and reasoning, not
for instructions:

- Each one describes the codebase **as it was on the date in its filename**. File
  paths, function names, and line numbers in them go stale, and no attempt is made
  to update them afterwards.
- Steps are written for the maintainer's own machine and workflow, so some refer to
  personal configuration outside this repository (`~/.claude/...`), sibling
  repositories, or scratch output directories that are not published. Those
  references are recorded so the plan reads honestly, and are not something a
  contributor needs or can reproduce.
- Where a plan and the current code disagree, **the code is right**.

For documentation that is kept current, start from the [README](../../README.md)
and the guides it links: [provider setup](../provider-setup.md), [truth and
pricing](../truth-and-pricing.md), and [adding a provider](../adding-a-provider.md).
